Next.js 14 — The Main Framework

⚡
Next.js 14
v14.2.15 · App Router · React Framework
FrameworkCore

What it is: Next.js is a framework built on top of React. It adds superpowers: server-side rendering, file-based routing, API routes (your own backend), image optimization, and more — all in one package.

Why we use it: Instead of React alone (which only works in the browser), Next.js can also run on the server. This means faster page loads, better SEO, and the ability to write backend code (API routes) in the same project.

App Router (the new way in Next.js 14)

Every folder inside src/app/ becomes a URL route automatically:

src/app/
├── page.tsx          → Opens at: localhost:3000/
├── movie/[id]/
│   └── page.tsx      → Opens at: localhost:3000/movie/123
├── search/
│   └── page.tsx      → Opens at: localhost:3000/search
└── dashboard/
    └── page.tsx      → Opens at: localhost:3000/dashboard

Server vs Client Components

// SERVER component (default) — runs on server, no hooks
export default function Page() {
  return <h1>Hello</h1>
}

// CLIENT component — runs in browser, can use hooks
'use client'
import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>{count}</button>
}

API Routes (your own backend)

Files inside src/app/api/ become REST API endpoints — no Express needed!

// src/app/api/favorites/route.ts  →  localhost:3000/api/favorites
export async function GET() {
  return Response.json({ message: 'Hello from backend!' })
}
💡 Simple rule: If a component uses useState, useEffect, or any hook → add 'use client' at the top. Otherwise, it's a server component by default.

TypeScript — Type-Safe JavaScript

🔷
TypeScript
v5.6 · Superset of JavaScript
Language

What it is: TypeScript is JavaScript with types. It catches mistakes before your code runs — like using a string where a number is expected.

// Without TypeScript (JavaScript) — no error, but crashes at runtime
function greet(user) {
  return user.name.toUpperCase()  // crashes if user is undefined
}

// With TypeScript — error shown immediately in editor
interface User { name: string; age: number }

function greet(user: User) {
  return user.name.toUpperCase()  // always safe!
}

In our project — types like Movie, WatchlistItem, FavoriteItem are defined in src/types/index.ts and used everywhere.

💡 TypeScript files use .ts (plain) or .tsx (with JSX/components) extension.

Framer Motion — Animations

🎬
Framer Motion
v11 · React Animation Library
Animation

What it is: A library that makes React components animate smoothly. You just describe the start and end state — Framer Motion handles everything in between.

// Replace <div> with <motion.div> and add animation props
import { motion } from 'framer-motion'

// Fade in when component mounts
<motion.div
  initial={{ opacity: 0, y: 20 }}    // start hidden, 20px below
  animate={{ opacity: 1, y: 0 }}     // animate to visible, normal position
  transition={{ duration: 0.4 }}     // takes 0.4 seconds
>
  Hello!
</motion.div>

// Scale on hover + click
<motion.button
  whileHover={{ scale: 1.05 }}
  whileTap={{ scale: 0.95 }}
>
  Click me
</motion.button>

AnimatePresence — animate when something disappears

import { AnimatePresence, motion } from 'framer-motion'

// The exit animation plays when isVisible becomes false
<AnimatePresence>
  {isVisible && (
    <motion.div
      initial={{ opacity: 0 }}
      animate={{ opacity: 1 }}
      exit={{ opacity: 0 }}     // this plays on removal
    />
  )}
</AnimatePresence>

We use it for: hero banner fade, movie card hover overlay, trailer modal zoom, video hover card spring animation, search dropdown.

NextAuth.js v4 — Authentication

🔐
NextAuth.js
v4.24 · Full Auth Solution for Next.js
AuthSecurity

What it is: NextAuth handles everything related to logging users in — Google login, email/password, sessions, JWT tokens — so you don't have to build it from scratch.

How Authentication Works (simple version)

User clicks "Sign In"
→
NextAuth shows login options
→
User logs in (Google/Email)
→
NextAuth creates a JWT token
→
Token stored in cookie
→
User is now "logged in"

Setup — src/lib/auth.ts

import { NextAuthOptions } from 'next-auth'
import GoogleProvider from 'next-auth/providers/google'
import CredentialsProvider from 'next-auth/providers/credentials'

export const authOptions: NextAuthOptions = {
  providers: [
    GoogleProvider({                            // Google login
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET
    }),
    CredentialsProvider({                       // Email + password login
      credentials: {
        email: { type: 'email' },
        password: { type: 'password' }
      },
      async authorize(credentials) {
        // Check credentials — return user object if valid, null if not
        if (credentials.email && credentials.password.length >= 6) {
          return { id: credentials.email, email: credentials.email }
        }
        return null
      }
    })
  ],
  session: { strategy: 'jwt' },    // store session as JWT token
  pages: { signIn: '/login' }         // custom login page
}

Using Auth in Client Components

'use client'
import { useSession, signIn, signOut } from 'next-auth/react'

function MyComponent() {
  const { data: session, status } = useSession()

  if (status === 'loading') return <p>Loading...</p>

  if (!session) {
    return <button onClick={() => signIn()}>Sign In</button>
  }

  return (
    <div>
      <p>Hello {session.user.name}!</p>
      <button onClick={() => signOut()}>Sign Out</button>
    </div>
  )
}

Using Auth in Server Components / API Routes

import { getServerSession } from 'next-auth'
import { authOptions } from '@/lib/auth'

// In API route — check if user is logged in
export async function GET() {
  const session = await getServerSession(authOptions)

  if (!session) {
    return Response.json({ error: 'Not logged in' }, { status: 401 })
  }

  // User is logged in — session.user.id, session.user.email etc
  return Response.json({ user: session.user })
}

Protecting Routes with Middleware

// src/middleware.ts — runs on EVERY request before the page loads
import { withAuth } from 'next-auth/middleware'

export default withAuth({
  callbacks: {
    authorized: ({ token }) => !!token  // true = user has a token = logged in
  }
})

export const config = {
  matcher: ['/dashboard/:path*']   // only protect /dashboard
}
💡 How it works: If someone tries to visit /dashboard without being logged in, the middleware checks the JWT token. No token → automatically redirects to /login. The user never sees the protected page.

Environment Variables Needed

NEXTAUTH_URL=http://localhost:3000           # your app URL
NEXTAUTH_SECRET=some-random-long-string      # used to sign JWT tokens
GOOGLE_CLIENT_ID=from-google-console        # from console.cloud.google.com
GOOGLE_CLIENT_SECRET=from-google-console

TanStack Query v5 — Data Fetching

🔄
TanStack Query (React Query)
v5.59 · Server State Management
Data FetchingCaching

What it is: A library that handles fetching, caching, and updating data from APIs. It solves the most common problem: "How do I show loading, handle errors, and cache data so I don't re-fetch every time?"

useQuery — Fetch Data

import { useQuery } from '@tanstack/react-query'

function MovieList() {
  const { data, isLoading, isError } = useQuery({
    queryKey: ['popular-movies'],        // unique cache key
    queryFn: () => fetch('/api/movies').then(r => r.json()),
    staleTime: 1000 * 60 * 5,             // cache for 5 minutes
  })

  if (isLoading) return <Skeleton />
  if (isError)   return <p>Error!</p>
  return <MovieGrid movies={data} />
}

useMutation — Send Data (POST / DELETE)

import { useMutation, useQueryClient } from '@tanstack/react-query'

function AddFavoriteButton({ movie }) {
  const qc = useQueryClient()

  const { mutate } = useMutation({
    mutationFn: () => fetch('/api/favorites', {
      method: 'POST',
      body: JSON.stringify(movie)
    }).then(r => r.json()),

    onSuccess: () => {
      qc.invalidateQueries({ queryKey: ['favorites'] }) // refresh favorites list
      alert('Added!')
    }
  })

  return <button onClick={mutate}>Add to Favorites</button>
}

useInfiniteQuery — Infinite Scroll

const { data, fetchNextPage, hasNextPage } = useInfiniteQuery({
  queryKey: ['popular', 'infinite'],
  queryFn: ({ pageParam }) => tmdbApi.getPopular(pageParam),
  initialPageParam: 1,
  getNextPageParam: (lastPage) =>
    lastPage.page < lastPage.total_pages ? lastPage.page + 1 : undefined
})
💡 Key benefit: If you visit the same page twice, TanStack Query serves the cached data instantly instead of fetching again. Cache lasts 5 minutes in our app.

Redux Toolkit — Global State

🗃️
Redux Toolkit
v2.3 · Global State Management
State

What it is: A way to store data that multiple components need to share — like user ratings — in one central place (the "store").

// Define a slice (a piece of the store)
const ratingsSlice = createSlice({
  name: 'ratings',
  initialState: { ratings: {} },
  reducers: {
    rateMovie(state, action) {
      state.ratings[action.payload.movieId] = action.payload.rating
    }
  }
})

// In a component — read and update state
const ratings = useAppSelector(state => state.ratings.ratings)
const dispatch = useAppDispatch()
dispatch(rateMovie({ movieId: 123, rating: 8 }))

In PKFLIX: Redux stores the user's movie ratings. Ratings are also saved to localStorage so they survive a page refresh.

📝 Note: TanStack Query handles server data (from APIs). Redux handles client-only state (ratings, UI preferences). Use the right tool for each job.

GraphQL

Hasura — GraphQL Database Backend

🌐
Hasura GraphQL Engine
Cloud · PostgreSQL Backend
BackendDatabase

What it is: Hasura connects to a PostgreSQL database and automatically generates a GraphQL API for it — no backend code needed. You get instant CRUD operations (Create, Read, Update, Delete).

Our Database Tables

TableColumnsWhat it stores
favoriteid, movie_app_id, title, overview, movie_poster_path, added_atUser's favorite movies
watchlistid, movie_app_id, title, overview, movie_poster_path, added_atMovies to watch later

How we call Hasura from API Routes

// In src/app/api/favorites/route.ts (SERVER SIDE ONLY)
await fetch(process.env.HASURA_URL, {
  method: 'POST',
  headers: {
    'x-hasura-admin-secret': process.env.HASURA_ADMIN_SECRET  // secret stays on server!
  },
  body: JSON.stringify({ query: 'query { favorite { id title } }' })
})
⚠️ Security: The HASURA_ADMIN_SECRET must NEVER go to the browser. That's why we put all Hasura calls inside API routes (server-side). The NEXT_PUBLIC_ prefix exposes variables to the browser — never put secrets there.

React Intersection Observer — Infinite Scroll

👁️
react-intersection-observer
v10 · Visibility Detection
Scroll

Tells you when an element becomes visible on screen. We attach it to a hidden div at the bottom of the movie grid — when that div comes into view, we load the next page of movies.

import { useInView } from 'react-intersection-observer'

const { ref, inView } = useInView({ threshold: 0.1 })

// When the invisible div scrolls into view...
useEffect(() => {
  if (inView && hasNextPage) fetchNextPage()  // load next page!
}, [inView])

// Put this at the bottom of the list
<div ref={ref} />  // invisible sentinel div

Movie Details Page
src/app/movie/[id]/page.tsx

When you click a movie, Next.js routes to /movie/123 where 123 is the TMDB movie ID. Three parallel API calls fire at once:

Netflix-Style Video Hover Card
src/components/movie/VideoHoverCard.tsx

This is the signature Netflix feature. Hover over any movie card for 700ms and a bigger preview card pops up with the trailer playing silently.

Mouse enters movie card

Immediately prefetches movie details (so clicking feels instant). Starts a 700ms timer.

700ms passes without moving away

Records the card's position on screen using getBoundingClientRect().

VideoHoverCard renders via Portal

createPortal(…, document.body) — appended directly to <body>, escaping all overflow clipping. Position calculated to stay inside the viewport.

Trailer fetches and plays muted

Backdrop image shown first. YouTube iframe loads with ?autoplay=1&mute=1. After 1.2 seconds, backdrop fades out to reveal video.

User can click 🔇 to unmute

Changes the isMuted state. The iframe's key prop changes → React remounts the iframe with mute=0 → video restarts with sound.

💡 Shared close timer: Moving the mouse from the card to the hover card doesn't close it. A 250ms delay timer starts when you leave the card — entering the hover card cancels that timer. Elegant!

Continue Watching
src/hooks/useContinueWatching.ts

Every time you open a movie's detail page, the app automatically records it in "Continue Watching" using a custom hook:

// This hook is called in MovieDetailsPage.tsx
useContinueWatching(movieId, movie.title, movie.poster_path)

// Inside the hook — fires once when the page loads
useEffect(() => {
  if (!session) return   // only if logged in

    method: 'POST',

Complete Authentication Flow

User visits /dashboard

Next.js middleware checks for a JWT token in the cookie.

No token found

Middleware redirects automatically to /login before the page even renders.

User signs in (Google or demo credentials)

NextAuth verifies the identity. For Google: OAuth flow. For credentials: the authorize function runs.

NextAuth creates a JWT token

Stores it as an HTTP-only cookie. Contains user ID and email. Expires by default in 30 days.

User redirected to /dashboard

Middleware sees the token → allows access. Dashboard fetches personalized data.

Every API route checks the session

getServerSession(authOptions) → if no valid session, returns 401 Unauthorized.

API Routes — Your Backend
src/app/api/

These files are your own Node.js backend, running inside Next.js. They handle auth checking and database operations:

RouteMethodsWhat it does
/api/auth/[…nextauth]GET, POSTNextAuth handler — handles all sign in/out logic
/api/favoritesGET, POST, DELETERead, add, remove favorite movies from Hasura

Security. The Hasura admin secret must stay on the server. API routes run on the server, so they can safely access process.env.HASURA_ADMIN_SECRET. Browser code cannot.

Browser
  → TanStack Query (useQuery)
    → Axios (tmdb.ts)
      → TMDB API (https://api.themoviedb.org/3)
        ← Returns: movies, posters, trailers, cast

═══════════════════════════════════════════════════
  USER DATA (favorites, watchlist — auth required)
═══════════════════════════════════════════════════
Browser
  → TanStack Query (useMutation / useQuery)
    → fetch('/api/favorites')   ← YOUR backend
      → API Route (Next.js server)
        → checks session with getServerSession()
          → if valid: queries Hasura GraphQL
            → Hasura ↔ PostgreSQL database
              ← Returns: user's favorites

═══════════════════════════════════════════════════
  AUTH FLOW
═══════════════════════════════════════════════════
Browser
  → signIn() from next-auth/react
    → /api/auth/[...nextauth]  ← NextAuth handler
      → validates credentials (Google or email/password)
        → creates JWT token
          → stores in HTTP-only cookie
            ← Browser now has a session
